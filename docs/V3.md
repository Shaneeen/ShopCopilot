## 3. What the simulator actually does

Same as `docs/competition_specification.md` §2 and `evaluator/local_evaluator.py:216`:

1. Hidden `intent_card` is **not in** `data/public_set.jsonl` — evaluator builds it at runtime from `catalog` via `intent_card(product)`: `hard_constraints[0:2]` + `soft_preferences[2:4]` (180-char truncation, mid-word cut in ~5% — backoff heals it).
2. `initial_message()` sends turn-1 based on scenario (buying discloses hard constraint, browsing vague: `"I'm looking for {category}, but I'm still exploring."`).
3. Loop 1..10: `agent.respond(session_id, user_message, turn, 10)` → `{message, ask_attribute, recommendations[10]}`. If target `parent_asin` in recommendations → hit. Else `customer_reply(ask_attribute)` string-matches `ask_attribute` against hidden card → `For that: <values>` or `no preference` (boundary).
4. `metric_summary()` → Hit@10, MRR (miss=0), MTTC (miss=11), `TechnicalScore=0.5*Hit+0.3*MRR+0.2*clip((11-MTTC)/10)`.
5. Hidden 800 uses identical code, same 40/40/15/5 mix, new `parent_asin`s. Tune on `dev_split` (160), never on public 200 or holdout.

## 4. What shipped

### 4.1 v2 (why it wins) — see IMPLEMENTATION_V2.md §2-3
- **Guarantee pool** `retrieval/token_index.py`: Boolean inverted index (50k docs, 95.5k terms, 3.5s build, `_LOOKUP_CACHE`), greedy token-group backoff, price-gated fail-open. Priority-union front-loads exact AND set; over-generality (>200) pads with corroborated/popular members. `filters.apply_filters(..., token_index)` O(1) token-set membership.
- **Ranking v2** `ranking/features.py + deterministic.py`: `coverage = Σ w·idf·[group⊆doc]` (stale 0.3), `(violations, -coverage, -relevance, -popularity, asin)`, `retrieval_normalization: minmax` (+1.5pp), `browsing_popularity_bump: 0.05`.
- **Clarification 8-gate** `conversation/clarification.py`: exhausted → turn-guard (9) → confident (full coverage + margin>0.15) → wildcard ×2 (`other_max_asks:2`) → over-generality (AND>200 → set-splitting entropy) → agreement (inferred, decay 0.9) → entropy fallback. Askable excludes `brand`/`category`.
- **State lifecycle** `conversation/state.py`: per-value contradiction staling (0.3, re-affirmation recovers), inferred decay, no wholesale erase on route flip/override.
- **Fixes that paid**: category regex stop at commas (+14.5pp), `;`-merge same-field fragments, no mid-word truncation, `constraint_token_groups` raw tokens.
- **LLM tier built but OFF** `ranking/llm_reranker.py`: twins/margin gates, `blend_epsilon:0.15`, `feature_flags.enable_llm_reranker: false`.

## 6. How to improve

### 6.1 Speed / latency (aim p50 <150ms, wall 100-case <60s)
1. **ProcessPool for CPU:** `ProcessPoolExecutor` when `--arms no-llm`; each worker builds its own `TokenIndex`/`FTS` handle — no GIL/`_conn_lock` contention.
2. **Kill double retrieval:** guard `pool_diagnostics` behind `--diag` or reuse `agent._preview_state` cache. Saves ~40% per turn.
3. **Cache semantic matrix:** memoize `pseudo_attributes.py` tokenization and `retrieval/semantic.py` hashed TF-IDF per `constraint_token_groups` key.
4. **Fixture the tests:** `pytest.fixture(scope="module")` sharing one `catalog_lookup`/`TokenIndex`.

### 6.2 Accuracy (aim Hit 0.88+, buying recovered, reclaim 2 sessions)
1. **Buying rank-miss / full-pool lever:** partial window 100–120 or retrieval-rank tie-break ahead of popularity; sort over-generality padding by `coverage_weighted_popularity` + `coverage×idf`.
2. **MTTC frontier:** grid `clarification.margin_stop` × `other_max_asks` via `scripts/run_experiment.py --grid`; pick Hit/MTTC Pareto.
3. **Extraction:** boundary phrasebook already covered by `_has_no_preference`; no further work unless forensics shows residue.

## 9. For the reviewer — central thesis

**Thesis:** *The best shopping agent does not maximize retrieval quality per turn; it maximizes information gained per conversational turn.*

Most teams: `BM25 + embeddings → 50-100 → LLM rerank → ask when needed`.

Ours: `query → estimate uncertainty (AND set size via TokenIndex, ~195/200 >200) → identify most useful missing attribute → ask one question → collapse space → rerank → stop only if worth it`. Maps to MTTC.

```
Turn 1 candidate space 7,842 → ask "use_case" (7842→612) > "color" (7842→6000)
Turn 2 612 → ask "material" (612→74) > "price" (11%)
→ target in top-10 at #1 → STOP (confidence 82%, gain +3% not worth turn)
```

**Three intelligent decisions (built):**
1. *What to retrieve* — multi-route lexical/semantic/category/constraint via Hybrid RRF k=60 + guarantee pool front-load.
2. *What to rank* — `(violations, -coverage×IDF×salience, -relevance minmax, -popularity, asin)` + contradiction penalties + inferred bonus-only.
3. *What to ask next* — **differentiator:** 8-gate: `turn-guard 9 → confident (full+margin 0.15) → wildcard×2 → over-generality set-splitting entropy → agreement inferred → entropy fallback`. Askable excludes brand/category. `Question Value = E[Δ uncertainty]/1 turn`.

**Adaptive stopping & mode shift:** Buying vs Browsing as continuous weight shift + per-value staling (no wholesale erase).

**What NOT to pitch:** "advanced LLM / vector DB / multi-agent" — out-of-scope and common.

**One-line carry forward:** v2 is recall-first AND information-efficient: guarantee pool + coverage×idf×salience + 8-gate maximum-disambiguation. Audit repairs made extraction correct and ranking complete; next win is partial competition window + MTTC frontier grid + (optionally) gated free-LLM if true bench clears thresholds. Keep submission deterministic unless gates pass.
