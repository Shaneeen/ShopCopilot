## 2. What P2 Gives to P3 — The 200 Candidate Contract

`INTEGRATION_CONTRACTS.md:65` — Retrieval ↔ Ranking

```python
# P2 provides:
candidates: list[Candidate] = HybridRetriever.search(query, state, top_k=200)
# Candidate shape (neeshops/retrieval/base.py:13):
#   parent_asin: str   # must exist in catalog_lookup
#   score: float       # raw retriever score, will be min-max normalised in merge
#   source: str        # "bm25" | "semantic" | "bm25+semantic"

# P3 consumes:
Ranker.rank(candidates, catalog_lookup: dict[str,dict], state: ConversationState, top_k=10)
  -> list[Recommendation(parent_asin, score, reason, source)]  # ordered best-first, len<=10
```

Rules:
- `state` is read-only — never mutate `constraints`, `asked_attributes`, `history`.
- `Candidate` is lighter than `Recommendation` — no `reason` field (ranking-stage concept).
- `is_available() -> bool` must never raise — `HybridRetriever` checks it before calling `search()`. Missing catalog, disabled flag, corrupt index => fallback to BM25, never empty pool, never crash.
- `catalog_lookup` may be `{}` — P3 handles it, but P2 must not inject fake ASINs.

## 3. Pinpoint Narrowed: What Must Be Fulfilled BEFORE Passing 200 to P3

Every `respond()` turn, before P3 ranks, P2 must deliver a **valid, deduped, filtered, weighted 200**:

| Step | File | Done Check |
|------|------|------------|
| 1. Route-aware weights | `hybrid.py:weights_for_route()` reads `config/default_strategy.json:retrieval.buying/bm25_weight=0.7` or `retrieval.browsing/bm25_weight=0.3` | No hardcoded weight outside config |
| 2. BM25 path | `bm25.py` indexes real fields `title,categories,features,details,store,description` via SQLite FTS5, cached at `<catalog>.fts.db`, lazy-built, `is_available()` checks catalog exists | Returns valid ASINs on 50k catalog |
| 3. Semantic path | `semantic.py:SemanticRetriever.search()` — lightweight in-memory (numpy matrix + cosine or small ANN), gated by `NEESHOPS_ENABLE_SEMANTIC_RETRIEVAL`/`feature_flags.enable_semantic_retrieval`, embeddings built once persisted/loaded, not rebuilt per turn | `is_available()` false when disabled/missing dep => Hybrid skips it |
| 4. Metadata filtering | `filters.py:apply_filters(candidates, catalog_lookup, state)` — budget vs `price`, category vs `categories`, soft text-containment for `color/material/brand` across title/.../store (catalog has no discrete fields — fail-open, never punish sparse metadata). `size/style/feature/use_case` extend `DEFAULT_FILTERS` as text filters. | `buying` hard constraints narrow, `browsing` stays diverse |
| 5. Hybrid merge | `candidate_merge.py:merge_weighted({bm25:[], semantic:[]}, weights)` — min-max normalise each retriever's scale then weighted sum, dedup by `parent_asin` with `source` concatenated `bm25+semantic`, deterministic for fixed config | Hybrid functional, tested |
| 6. Truncation | `retrieval.candidate_limit=200` (config) — `HybridRetriever.search(..., top_k=200)` returns <=200. P3's `ranking.rerank_limit=40` will further slice inside ranker, so your 200 is the pre-rank pool that bounds P3's LLM cost. Agree count: you emit 200, P3 reranks top 40. | Deterministic order, valid ASINs only |
| 7. Fallback | Semantic disabled/corrupt/timeout => full BM25 results returned alone | `tests/test_retrieval.py` passes |

Failure = P3 gets empty/short/invalid pool => `Hit Rate@10=0`, `MRR=0` regardless of ranking quality.

## 4. Build Order (No P3 Interference)

1. `python scripts/setup_catalog.py` — inspect 3 real queries, record candidate recall (target ASIN in pool?).
2. Verify BM25 field weights match organiser weak starter (`bm25.py:32`).
3. Choose embedding: `sentence-transformers/all-MiniLM-L6-v2` (80MB, <2B limit) or TF-IDF numpy baseline — pin version, add single dep, document in `retrieval/README.md`.
4. Build index once: `scripts/build_semantic_index.py` -> `data/semantic.index.npy` + `data/semantic.meta.json` (gitignored), load in `SemanticRetriever.__init__`.
5. `SemanticRetriever.search(query, state, top_k)` — embed query, cosine search, return `list[Candidate(source="semantic")]`, `is_available()` fail-soft.
6. Test: `merge_weighted` dedup, weighting, disabled mode, corrupt index, latency <100ms on 50k.
7. Extend `filters.py:DEFAULT_FILTERS` for `material/color/brand` soft filters (already) then `size/style`.
8. Never touch `hybrid.py` merge logic beyond weights — it already handles new source.

Create `tests/test_semantic_retrieval.py`:
- enabled returns valid ASINs, disabled returns fallback, corrupt index returns BM25, empty query returns [], duplicate ASIN merged once, deterministic.

## 7. Communication With P3 — What to Sync

- Candidate count: you emit 200, P3's `HeuristicRanker` reranks 40 then returns 10 — confirm truncation point.
- Score semantics: you give raw BM25 FTS5 rank + cosine similarity — they are incomparable scales, merged via min-max inside `merge_weighted` before P3 sees them.
- `source` string format: `"bm25+semantic"` concatenated — P3 already handles mixed source per `TEAM_WORKSTREAMS.md:444`.
- `ConversationState.route` drives your weights — P1/P5 set it, you read it.
- Token/latency: your semantic search must be <100ms so P3's optional `LLMReranker` stays under `MTTC` budget (`problem_statements.md:22`).

Do not coordinate via code edits to `neeshops/agent.py` or `neeshops/ranking/**` — flag interface changes in PR, P5 merges.
